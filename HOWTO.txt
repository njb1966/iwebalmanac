Independent Web Almanac Publishing HOWTO
========================================

This site is built with Astro and Markdown content files.

The current site source lives in the repository root. The archived older site
folders are not part of the active publishing workflow.


Basic workflow
--------------

1. Choose the section for the piece.

   Content folders:

   - src/content/fiction/
   - src/content/essays/
   - src/content/reviews/
   - src/content/interviews/
   - src/content/resources/

2. Copy the template for that section.

   Example:

   cp src/content/essays/template.md src/content/essays/my-new-essay.md

3. Edit the new Markdown file.

   Keep the template file itself as a draft reference. Do not publish the
   template files.

4. Leave draft mode on while writing.

   draft: true

5. When the piece is ready, change it to:

   draft: false

6. Build the site.

   npm run build

7. Preview locally if desired.

   npm run preview

   The preview server normally runs at:

   http://127.0.0.1:4321/


URL structure
-------------

URLs are created from the content folder and filename.

Example:

src/content/essays/my-new-essay.md

becomes:

https://iwebalmanac.net/essays/my-new-essay/

Use simple lowercase filenames with hyphens:

good:

my-new-essay.md

avoid:

My New Essay.md
my_new_essay.md
essay-final-v3.md


Common frontmatter
------------------

Every content file starts with frontmatter between --- lines.

Example:

---
title: "Why Process Still Matters"
description: "A short summary used on listing pages and in RSS."
date: 2026-06-06
author: "Independent Web Almanac"
featured: false
draft: true
---

Required fields:

- title
- description
- date

Common optional fields:

- author
- editor
- processNote
- disclosure
- featured
- draft


Publishing and drafts
---------------------

draft: true

The piece is hidden from the public site, RSS feed, and sitemap.

draft: false

The piece is published.

Only set draft: false when the piece is ready to appear publicly.


Featured pieces
---------------

featured: true

The piece is eligible to appear as the homepage lead article.

If more than one published piece has featured: true, the newest one wins based
on the date field.

For ordinary pieces, use:

featured: false


Section-specific fields
-----------------------

Essays may include:

topic: "Writing craft"

Fiction may include:

format: "Short story"

Allowed fiction formats:

- Short story
- Flash fiction
- Serial
- Excerpt
- Experimental

Reviews may include:

subject: "Example Book Title"
subjectType: "Novel"
rating: "Recommended"

Allowed review subject types:

- Novel
- Story collection
- Software
- Tool
- Platform
- Other

Interviews may include:

guest: "Guest Name"
role: "Writer"

Resources may include:

resourceType: "Guide"

Allowed resource types:

- Guide
- Reference
- Template
- Case study
- Comparison


Writing body content
--------------------

After the frontmatter, write normal Markdown.

Examples:

# Heading

## Subheading

Paragraph text.

- List item
- List item

> Block quote

[Link text](https://example.com)


AI/process notes
----------------

AI-assisted work is allowed. Disclosure is optional unless the process is
relevant to the piece or useful to the reader.

If a process note is useful, add:

processNote: "Brief explanation of the workflow or editorial context."

If a disclosure is useful, add:

disclosure: "Brief disclosure text."

These fields appear on the article page when present.


Build commands
--------------

Install dependencies:

npm install

Build the static site:

npm run build

Preview the built site:

npm run preview

Run the development server:

npm run dev


Output
------

The built site is written to:

dist/

Do not edit files in dist/ directly. They are generated by Astro and will be
overwritten on the next build.


Current technical note
----------------------

The site currently uses Astro 5 because the local machine is running Node 20.
Astro 6 requires Node 22.

When the runtime is upgraded to Node 22, Astro can be upgraded later.
